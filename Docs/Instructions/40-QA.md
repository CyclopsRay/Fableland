# Fableland — QA / Testing Department

How we keep bugs out despite (a) one developer, (b) a dev host that often has **no
Godot/.NET toolchain**, and (c) a game whose core loop spans three layers. The answer
is a pyramid: cheap always-on checks at the bottom, expensive human playtests at the top.

---

## 1. The testing pyramid

```
        (5) Manual playtest protocols        — per milestone, seeded, checklisted
        (4) In-game debug harnesses          — seed field, Rest, Mist, tuning overlay,
                                               ShowDebugRanges, map view toggles
        (3) Pure-logic unit tests            — headless dotnet test on Scripts/Data + Map
        (2) Real build                       — dotnet build / Godot --headless (when available)
        (1) Static checks                    — every commit, no exceptions
```

### (1) Static checks — every commit
- Brace/paren balance in changed `.cs`; `.tscn` `ext_resource`/script paths resolve;
  `GetNode`/NodePath strings match the scene trees; exported-property assignments in
  scenes still point at existing members; no shadowed inherited members.
- Version trio in sync (`GameVersion.cs` / `VERSION` / Hud `VersionLabel`).
- Grep-audits worth running when touching the relevant systems:
  - `GD.Rand|new Random(` outside `DetRandom.NewSeed` → determinism leak.
  - Numeric literals in new gameplay logic → should be a table lookup (30-DATA §2).
- **Static checks miss type/API-existence errors** (Godot API surface!). Say so in the
  commit message when no real build ran.

### (2) Real build — whenever a toolchain is present
`dotnet build` at minimum; opening the Godot editor re-imports assets and surfaces
scene errors. If a session has a toolchain, spend the first minutes building HEAD —
catching a stale API break early beats debugging it inside a feature.

**Map content, headless (v0.10.6).** After touching tiles, tile art, the map builders, a
built-in map — or how a character or a foe moves through a SoftVolume — run the content
check. It needs no window and never starts a fight (it does simulate movement — the
swimming probe, at 8× — which took the whole check to roughly twelve seconds in v0.11.1;
the no-orphan walk below adds two):

```bash
Godot --headless --path . --import          # once in a new checkout/worktree, and after adding or repainting art
dotnet build Fableland.csproj
Godot --headless --path . res://Scenes/MapCreation/MapContentCheck.tscn    # exit 0 = clean
```

A new worktree has no `.godot/` import cache, so without the first line every sprite
"does not load" (KNOWLEDGE v0.10.8). Read the check's own exit status — not that of a
`| tail` after it.

It runs every Map Creation self-test and `TileSetAudit` (registry ↔ `.tile.json` sidecar ↔
PNG canvas), loads each tile's sprite and each hazard's scene, then builds every
`res://Maps/*.json` through `CombatMapRuntime` — the real run path — and checks it is playable:
one character spawn, respawns, a usable nest for both foe types, a goal marker for each goal
it claims to serve, tiles from one realm set. **Nudge parity** (v0.10.8): it builds a small
map with one piece of every category nudged off the grid, through the arena path *and* the
editor Playtest, and fails if any art node, collider, hazard or marker is not at the same
shifted spot in both — or if ground moved at all (MapCreation.gdd §2.3). Last, **coverage**
(v0.10.7): it asks the run's
own map selection, shipped maps only, about every kind of combat node an outer world can roll
(LV1–3 × each ordinary mission, the LV4 boss, × low / sea-level / high ground) and prints
`coverage <world> n/39`; a world with a kind no map serves fails, because that node would open
the legacy arena. Since v0.11.0 the same line also says whether the world ships **its own set**
— a map authored *for* each band (a `*` map serves a band but cannot be chosen for it) and a
boss arena — and a pool world missing any of the four fails. Each failure prints on its own
`FAIL` line.
**No orphan map** (v0.11.3): the same question the other way round. Every shipped map
must be dealt to at least one kind of node a run can produce — an outer node, or a zone-6
node wearing a pool world (LV5 × each ordinary mission, the LV6 core; `MapGDD.md` §7) — by
the two rules the run itself draws with. A map tagged for a world outside the pool fails by
name (it used to be a printed note, which is how Cloud Court stayed unreachable for two
versions); zone 6 wearing any pool world must find a map for every mission and a boss arena
for its core; Cloud Court must be dealt on the Palace of LOOING's high ground and nowhere
else in the outer worlds; and each map's art must be a realm of a world it is tagged for.
It prints one line — read the middle of it, a map dealt *only* in zone 6 is reachable but
barely:

```
reach    45 shipped maps: 44 are dealt in an outer world · 1 only where zone 6 wears its world (seashore_5.json) · 0 never · Cloud Court on PL high-ground, 12 kinds of node
```

Broken three ways, each failing by name: Cloud Court's map put back on world `CC` (`orphan
map — … tagged for world 'CC', which is not in the overworld pool`), the same map tagged for
every band, and zone 6 made to honour a hardship level (its core is dealt ordinary maps).
(`Godot` = `/Applications/Godot_mono.app/Contents/MacOS/Godot` on the dev Mac.)

**Swimming, water, currents and waterfalls (v0.10.9, v0.11.1)** are the last part of the
same check (`MapContentCheckPhysics.cs`, MapCreation.gdd §2.2a):

- **Volume parity.** One map with a sea on a Farview layer, a flipped current and a bubble
  column is built through the arena and through the Playtest; both must produce the same
  volumes at the same places with the same tuning, and neither may build a looping layer's
  water or a layer's that did not ask for Collision.
- **Every medium can be swum up in.** Each medium in the registry is asked what a standard
  fighter holding Up for three seconds does in it (`SoftVolumeSet.PredictSwimSpeed`); under
  0.5 m/s fails — that kind is a pit with no way out.
- **The physics probe.** The real Pomegraknight — and a crab — are put into the shipped
  kinds through the Playtest and the simulation is run (at 8× speed; each tick is still
  1/60 s). It drives the game's input actions, measures where the body actually goes, and
  prints one `physics` line per stage:

  ```
  physics  sea       sinks 3.0 m/s · swims 5.5 m/s across (runs 10.0) while sinking 3.0 · up 2.5 m/s · down 8.5 m/s · up-and-across 5.5 / 2.5 m/s
  physics  sea jump  a jump in open water rises 3.0 m · off the sea bed 3.0 m (air jump 8.3 m) · at the surface the head stays within 0.2 m of it, and a jump clears the water by 2.1 m
  physics  sea climb holding Up 2.5 m/s · tapping Jump 10.0 m/s (5 launches in 1.5 s: the 0.3 s cooldown allows 6) · both 10.7 m/s
  physics  bubbles   lift 4.0 m/s · swum up 9.5 m/s · across the joint of two tiles never faster than 4.0 m/s
  physics  bamboo    floats down 1.0 m/s · holding Up climbs 8.6 m/s · a jump inside rises 5.9 m · tapping Jump climbs 19.4 m/s (4 launches in 1.0 s) · at the top the head stays within 0.1 m of it, and a jump clears it by 5.1 m
  physics  foe       a crab falls through a bamboo at 20.2 m/s (a fighter floats at 1.0)
  physics  kelp      in the sea: up 1.0 m/s · across 4.0 m/s
  physics  canal     in the shipped Forgotten City map, built as a run builds it, a fighter swims up 2.0 m and jumps out onto the bank: yes
  physics  canal     in the shipped Forgotten City low-ground map, built as a run builds it, a fighter swims up 2.0 m and jumps out onto the bank: yes
  ```

  It fails when a kind stops doing what its tuning says. A fighter must sink at the drop,
  swim across at `stagnationIndex ×` its top speed with the drop underneath, rise at that
  speed minus the drop and descend at it plus the drop; a jump inside a volume must rise
  what the model predicts, come back once its cooldown is over and **never launch more
  often than the cooldown allows** (Jump is tapped every other tick and the launches are
  counted), and carry the body out through a surface; a swimmer holding Up must rest with
  its head at the surface; a body must be
  carried at `flowX` / `flowY` — and no harder across the joint of two tiles — and keep
  sinking after drifting out of a current; a foe must not float. The expectations come
  from the tile kinds' own tuning and from the model (`SoftVolumeSet.PredictSwimSpeed`,
  `PredictJumpRise`), so **retuning a number does not break the check — breaking the
  mechanism does**. Those printed lines are the numbers to quote in a design doc.

When a new tuned SoftVolume kind ships, give it a stage in the probe. When a kind's
footprint changes, the probe says so and asks for its layout to be updated. **When a map
ships a pool of swamp water, add the pool to `ShippedPools`** (`MapContentCheckPhysics.cs`):
the probe swims out of each one the way a player would — up to the bank, then a jump — and
fails a shipped map that holds swamp water and is not listed (v0.11.1; v0.11.0's low-ground
canal had banks 2 m over its water and failed this until it was made flush).

**Boss fights, headless (v0.10.11).** After touching a boss, its brain, a protagonist kit
that has a BOSS variant, `CharacterController`'s input or hit intake, combat sides, slope
tiles or a boss arena, run the boss check. It needs no window and takes about 25 seconds
(it simulates a few minutes of play at 8× speed; each tick is still 1/60 s):

```bash
Godot --headless --path . res://Scenes/Bosses/BossFightCheck.tscn      # exit 0 = clean
```

1. **Logic** — the virtual pad's edges (a tap is owed to the physics loop and the process
   loop separately), the rule scheduler (priority, one-shots, cooldowns, commitment), the
   boss table.
2. **Content** — every boss row's scene is a Foe-side boss fighter and recruits a real
   protagonist.
3. **Physics, on a stage of plain colliders** — PumpKing's head on the flat and on a 1:2
   slope; a fighter walking that slope; *sides*: groups, layers, camera, who reads the
   keyboard, the boss taking every hit with poise while the player keeps its i-frames, and
   each side's head striking the other side only (his brain is put to sleep for the part
   that counts HP, so every hit there is one the probe threw); *swimming* (v0.11.1): in one sea, the
   player's Up and Down must swim the player and leave a boss sinking at the drop, and his
   pad's must swim him and leave the player sinking; and *his rules, one at a
   time*, each in the one situation it exists for: set down 5 m from his perch he walks back
   and stands; knocked off a ledge 5 m up he walks under it and jumps back on; he turns to
   face the player; a head that is beside the player but cannot touch them (a wall stands at
   their shoulder) he sets off; a head rolling away from a player who got behind him he
   calls back, and has it again a reload later.
4. **The fight** — the real `Arena.tscn`, staged the way debug mode stages a boss, on the map
   the run's own selection deals: the boss opens on the perch farthest from the player, pumps,
   bowls, and the head runs the slope and hurts a player standing at its foot; the player
   walks the real tile slope without leaving the floor; pressed on his perch the boss leaves
   in Soul Form, lands on the other perch and comes back when pressed again; beating him
   resolves the mission, recruits him, and his body frees itself.
5. **Zone 6's own kits, and PumpKing's ultimate, the Black Prison** (`PumpKing.gdd`), on
   plain stages with crabs in pens. The prison probes press the pads themselves (the check
   steps a pad no brain owns):
   - **the owner's numbers** are pinned, the 8 m radius among them (v0.12.15);
   - **the timeline:** Q on an empty ring opens nothing; the full ring is spent and it opens
     where he aims; a second of warning holds nobody, grows nothing and refuses a recast;
     then it holds exactly 4 s and lets go;
   - **crabs inside:** one at the centre held (move, jump, silence, sight) and walking at half
     speed, back to full after; one 6 m off held too; one past the rim untouched;
   - **the recast:** free and once. It lands him on the nearest spot his body fits (the
     centre is put in the floor for him on purpose), and the 100-damage, no-shove blast — his
     head's 3 m, the prison's heart — hits the crab at the centre and neither the one 6 m off
     nor the far one;
   - **a foe's mind:** a level-6 crab beside him starts no Jump until let go, then jumps; a
     level-3 crab that had turned on him from 5 m loses him the tick the prison forms, is
     not turned by a blow, and turns again when let go;
   - **range and pumpkins:** the cast range, alone and from a 30 m aim; eight pumpkins on a
     seeded prison, exactly 0.5 s apart, hurting rooted crabs for a pumpkin's damage (twice
     that through a crab's Soft Shell);
   - **sides:**
     - a BOSS PumpKing's prison holds the player (5 m from its centre): the jump falls from 8
       to 4 m, the run is halved, Skill 1 is refused while the swing goes, and the view is
       darkened. Running out frees them, coming back catches them, and all of it returns when
       it ends;
     - **the walk-out:** a 10 m/s player caught 4 m from the centre runs out the tick its hit
       circle clears the 8 m rim (±4 ticks of (8 + 0.9 − 4) m at half speed);
     - the player's prison holds a boss: his senses lose a player 6 m off, Pump Up is
       refused while his head still flies, and a soul already cast flies at half speed.

**It was mutation-tested**: twenty-nine deliberate breakages, each run against the check
as it stands — the old head bug, a head that bounces at a change of slope or outruns its
cap, no floor snap, a head that ignores its side, a side offered its own as targets, a boss
that keeps the camera, joins the `player` group, keeps the keyboard, has no poise, ignores
its table row or gets i-frames, a brain never handed to the body, the wrong opening perch,
**each of his seven rules removed in turn**, a "hold perch" that never jumps or never turns
to face the player, an attack button that no longer sets a rolling head off, no recruitment,
a pad that forgets the physics loop, a scheduler that ignores cooldowns, a boss arena that
is not preferred — and twenty-eight fail the check by name. The twenty-ninth (gating a
boss's hits on an i-frame timer nothing ever arms for it) changes no behaviour.

**The swimming stage (v0.11.1) was broken five ways** and failed by name each time: both
swim reads put back on `Input` (the swimming work as it was written, before fighters had
sides — four lines fail: the boss rises on the player's Up, dives on the player's Down, and
ignores his own pad twice), each read alone, swimming made Player-side only, and
`PlayerControls` no longer registering `move_up`. The map content check stays green under
the first and the last of those — it drives the player only, and registers the action it
presses — which is why this stage is in the boss check and never calls
`InputDefaults.Ensure()` itself.

**The Black Prison stage was broken thirty-three ways** and fails by name each time. The
mutants cover:
- the timeline, and each of the four holds;
- silence taking the basic attack, or ignored by a fighter or a foe;
- a foe's four sight rules, and the boss's senses;
- the pumpkins' pace and harm;
- the blink, a blink into the floor, the blast's damage and shove;
- the range, the recast's three limits, release, membership both ways;
- the veil, a soul at full speed, an empty ring, an unspent ring.

The first run let one through, a second recast. The probe pressed Q on a PumpKing the crab
beside him had just stunned, and a stunned body reads no button. The probe's PumpKing now
takes no stun, and it counts the press's own cue (`ult.recast`). See the hand-off note
`Docs/_handoff/pumpking-ult.md`.

The first round broke only two of the seven rules. Breaking the rest found two rules the
check could lose without noticing ("hold perch", "call back") and one caught by an
assertion about something else — which is why the rules probe exists and why the sides
probe now sleeps the brain (KNOWLEDGE.md, v0.10.11). **When you add a mechanism or a rule,
break it once, watch the check fail, and read which line caught it.**

The fight is not frame-deterministic: abilities and the brain run in the process loop, whose
frame times vary, so two runs differ in detail. The check's thresholds are behavioural (did
he throw, did the head arrive, did he change perch) and it has passed every run of many; if
it turns flaky, widen a time budget — not a mechanism.

**The run, headless (v0.11.0).** After touching the world pool, map generation, the save
format, `RunState`'s adventure flow, map selection, a shipped map, or how a boss is sized, run
the run check. It takes about a minute and plays real runs through real scene changes
(Arena → Map → Shelter → Event → RunOver), at 8× speed:

```bash
Godot --headless --path . res://Scenes/Run/RunWalkCheck.tscn      # exit 0 = clean
```

1. **The pool** — the eight worlds in their append-only order, each with a realm tile set, a
   map colour no other world is close to, and a boss; sixty seeds each draw five different
   pool worlds, home first, and between them every world; and the **six-world pool still
   generates what it did** for six recorded seeds (realms, every node's id, kind, level and
   mission, the road count) — that signature is what an old save depends on. **Today's pool
   of eight is pinned the same way** for eight seeds, recorded on v0.11.1: a new seeded
   choice (what a node is dealt) must take a stream of its own, so none of them may move.
   **What zone 6 is dealt** (v0.11.3): for twelve seeds, each of the six zone-6 nodes
   is dealt the same map when asked twice — the second time with the run's worlds listed in
   reverse — always a map of one of that run's own five worlds, for the node's mission, a
   boss arena for the core alone; between them the seeds wear every pool world.
2. **Saves** — a version-3 slot file loads onto the map it was saved on and stays there when
   written again; a new run records today's pool and comes back on its own map.
3. **Every shipped map, entered** — each of the 45 opens in the real Arena: an authored map,
   the mission running, the player inside it and not falling. Each boss arena has two
   perches within one Soul Form flight, stages the boss on one, and he gets a head away at a
   player who only stands — on all eight, the undersea one included. Then each boss arena
   again as the LV6 core would open it: the **stand-in crab** is staged on a perch, comes to
   rest on a floor and stays in the map (any of the eight can be the core's).
4. **The walk** — a real run per world: three cities, one per altitude band (the node is
   given the band and a mission, cycling so every pair turns up), each entered through
   `BeginAdventure`, checked (a shipped map of that world and band, the day's foe level, the
   player standing), played to its goal, and ended with the day — back on the map, a
   checkpoint written; then a hub and an event; then the capital on that world's own day
   band, where **the boss's HP, its bar and its damage must be the day's** (FOES §2, §8.2).
5. **Cloud Court** (v0.11.3) — the check finds a run with a Palace of LOOING node whose
   *own* band is high ground and which the run's own selection deals Cloud Court, writes
   nothing onto it, and goes in through `BeginAdventure`: the Cloud Court map opens, not
   VOID-touched, and is played to its goal. No Palace node on another band may be dealt it.
6. **The void** (rewritten v0.11.3) — all five LV5 nodes and the core of one run. Each
   must open an **authored map of one of the run's worlds** for its own mission — never the
   legacy stage — with the handshake saying `VoidTouched`; the backdrop and every piece of
   the map's art must wear the VOID treatment and nothing else may (hazard sprites, the
   `Hazards` node, foes, the player); the player stands, the mission runs, the first foe
   comes out of the map's nests inside the map, and the node completes. LV5 fights at foe
   level 7 and the core at 8 whatever the day; the core is dealt a boss arena, its stand-in
   crab (2800 HP) is on the field inside it; beating it ends the run in victory and deletes
   its save.

### (3) Pure-logic unit tests
The reason `Scripts/Data/` and map logic stay free of Godot types. Highest-value tests:
- **Map determinism:** same seed ⇒ byte-identical graph (serialize node ids/positions/
  edges → hash). Two different seeds ⇒ different hash. This single test guards the
  whole seed contract.
- **Map invariants (any seed, fuzz 100+ seeds):** the outer coast is one connected landmass with
  no detached outer islets; the static pentagonal VOID is within its target 1/30 area tolerance;
  five non-crossing, variable-width rivers each touch the VOID and coast, producing exactly five
  realm polygons; every realm has equal level-1/level-2 city totals with A/B sublevels and ranks
  LV4, both LV3s, `2-B`, `2-A`, `1-B`, `1-A` by VOID distance; every realm node reaches its `4-1` without a road
  entering another realm, a river, the VOID, or another road except at a shared node; exactly one
  LV3→LV4 approach per realm contains a Transportation Hub; each realm has 3–5 hubs and 4–6
  degree-two Event nodes; terrain is one of
  `low-ground`/`sea-level`/`high-ground`; TwistedReality only unlocks after the starting LV4,
  builds from a completed VOID-river peripheral city to the nearest city of the closest realm
  (or nearest LV5 from LV4), creates a midpoint Eidolon Shelter, rejects already-anchored
  endpoints, and observes its 4-day cooldown; zone-6 edges remain invisible; each outer combat node has a valid controlled field;
  function nodes devour only after a strict majority of their connected cities, and a devoured
  bridge endpoint breaks the bridge and releases its survivor.
- **FoeStats:** table values per level; `HasSkill1/2`, aggro/sight gates; evolution
  math (heal 30% of *new* max, +1 once, cap 8); spawn rule (level −2, min 1, no
  grandchildren).
- **Day-end pipeline:** step order (day → devour → CD tick → perish tick → NPC leave →

## 2. Bug workflow (mandatory, from CLAUDE.md)

1. **Reproduce** — with a seed if run-dependent; note version.
2. **Fix** — smallest change that respects the architecture.
3. **Caveat** — append to `KNOWLEDGE.md` "Caveats / gotchas": *symptom → rule → why*,
   tagged with the version. This is non-negotiable; it is the studio's memory.
4. **Regression hook** — if the bug class is testable, add it to the unit tests or the
   regression sweep so it can't silently return (e.g. the function-node road-HUB rule:
   "don't remove this or the 'connected but walled-off' bug returns").
5. Version bump + changelog line.

## 3. What history says to watch (from KNOWLEDGE.md — the bug taxonomy)

- **Godot API drift:** no `Label2D`; Control `mouse_filter` STOP eats `_UnhandledInput`
  clicks; `_Ready` runs inside `AddChild`; fonts via `GetThemeDefaultFont()`.
- **Geometry:** hit tests must be radius-aware; `DrawColoredPolygon` needs convex;
  sprite size ≠ collision size — check both.
- **Feel wiring vs feel output:** an effect can be wired correctly and still invisible
  (trauma² shake). Verify magnitude, not call sites.
- **State bookkeeping:** coyote-time jump forfeiture needed three fields, not one flag.
  When a rule reads "X per Y unless Z", expect dedicated bookkeeping and test the
  unless-path.
- **Map rendering:** outer coast fills must be submitted as convex strips (never a concave
  polygon); altitude contours and tint are decorative only; roads remain the only route cue.
  Changes to `MapRenderModel.Build` need a coast/contour/road visual sweep across several seeds.
